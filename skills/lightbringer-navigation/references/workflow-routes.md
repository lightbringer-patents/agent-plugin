# Workflow routes and fallbacks

Choose by the user's intended result. The routes below distinguish bundled skills from optional workflows; neither establishes tool access. Read only the selected specialist's instructions. If that skill is absent, use the connection's available guidance and tools for the same authorised scope; do not invent a substitute procedure or payload.

| User need | Specialist route | Result and boundary |
| --- | --- | --- |
| Establish or maintain shared company background | [company-context](../../company-context/SKILL.md) | A useful company brief; save only with intent to update shared context. Profile completion is not a general navigation prerequisite. |
| Decide protection priorities or revise an IP plan | [ip-strategy](../../ip-strategy/SKILL.md) | Evidence-based direction and, when requested and supported, a saved Strategy. Proposed actions do not execute themselves. |
| Capture an idea, develop its description or mine authorised sources | [innovation-capture](../../innovation-capture/SKILL.md) | Supported findings and, when authorised, a registered or enriched innovation. Exploration alone does not authorise saving or preparation. |
| Understand earlier technical disclosures | An installed prior-art-search workflow, otherwise available search guidance or the Lightbringer team | Search findings and feature comparisons, with actual evidence and report status. A professional opinion is a separate outcome; disclosure feedback does not establish novelty or freedom to operate. |
| Ask Lightbringer to prepare an innovation for patent filing | [patent-preparation](../../patent-preparation/SKILL.md) | A confirmed request to the Lightbringer team, with team follow-up before further work proceeds. Carry explicit patenting intent through necessary capture; do not infer a paid plan, professional assignment or immediate drafting. |

| Work on an active application, filing instructions or a prosecution response | An installed application workflow whose scope covers the request; otherwise the Lightbringer platform and patent team | Reuse the current application and professional work. Do not assume a broadly named patent-application skill exists or that patent-preparation executes drafting, filing or prosecution. Existing document reviews can use patent-review. |
| Seek professional advice, an attorney opinion, FTO work or portfolio management | The advertised service route, if supported; otherwise the Lightbringer team | Explain the requested scope and continuation. Do not use preparation requests, review comments or engineering feedback as substitute service orders. |

## Make the fallback useful

Lightbringer's [public MCP guide](https://lightbringer.com/our-platform/lightbringer-mcp) directs users to the application and patent team for patent-preparation, filing and prosecution progress. This is a service continuation, not evidence that every platform action is self-service or available to the connected user. The guide was consulted on 28 October 2026; advertised capabilities and actual record access govern what can be done now.

Prefer a record URL returned by the service or supplied in the current context. Otherwise link to the [Lightbringer application](https://app.lightbringer.com) and identify the innovation, application or review the user should locate. Explain what to view or discuss there, such as the current draft, a requested review, filing instructions or a question for the patent team. Do not fabricate deep links, buttons, contact details or platform procedures.

For work needing professional handling, direct the user to their existing Lightbringer patent-team contact or the available contact route in the platform. If no case or team contact exists, use the [public Lightbringer service page](https://lightbringer.com/our-platform/lightbringer-mcp) to find the current contact route. Keep any prepared question or handoff inline; sending it requires authorisation and an actual supported channel. Do not claim delivery, assignment, purchase or a service order from a referral.

Retain the goal, record reference, known state, unresolved question and requested next action so the user does not need to reconstruct the context. If progress cannot be read through MCP, say that it is unverified here and explain where to check it. Do not poll an innovation ID as an automated task or estimate a live professional milestone from elapsed time.
