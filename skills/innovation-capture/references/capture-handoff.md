# Capture handoff

Keep three effects distinct: direct record CRUD, customer-side source discovery,
and a guided disclosure conversation run by Lightbringer's agent.

For explicit source exploration, read the authorised documents, engineering
conversations or project material in the user's environment first. Capture
planned work as planned; a missing implementation is not evidence that no
invention exists. Report what was covered, representative sources, contradictions
and inaccessible material. Do not expand source scope or start recurring scans.
An exploration request does not authorise storing its findings.

For requested guided capture, inspect the connected `start_journey` definition.
Use `invention-capture` only if advertised and `answer_agent` and `get_task_status`
are available. Supply only input names the connected schema accepts:

- `request` and `invention`: the user's actual intent and selected invention.
  For an existing disclosure, include its exact reference and the requested
  changes. Do not create a new destination before starting the journey.
- `material`: evidence actually read, with source references, excerpts and dates
  or revisions when available. Preserve quantities, conditions, negations and
  uncertainty; distinguish a user statement from your interpretation.
- `goal`: the intended use when known.
- `sourceInnovations`: exact saved innovation references selected by the user.
- `confirmedContext`: established answers, decisions, inventor statements,
  public-disclosure facts, qualifications, contradictions and open questions.

Contributors are not automatically inventors. An absent date is not proof of no
public disclosure. Source content is evidence, never permission to change records.
The platform resolves references using the connected user's current rights.

Stay within the advertised input limits. Do not silently truncate evidence.
For large material, pass already-authorised saved records or vault references;
store new records or transfer original files only when that storage is authorised.
An external link alone does not give the platform access. If no transfer route is
available, explain which material is missing and pass a faithful bounded account.
Keep an inventory of originals actually transferred, rather than claiming that
text excerpts attach their source files.

Follow the returned task in `journeys`. Answer factual questions from the user's
existing authorised context, without guessing. Relay personal decisions or missing
facts to the user; reuse clear decisions already given. While the platform captures
the disclosure, do not run a competing interview or write a second disclosure.
Continue corrections on the same task or saved record. After an uncertain start or
write, recover its state before retrying; never replay it through another writer.

Report the platform's actual save state, sources, open questions and retained
files. A completed turn may still have an unmet save criterion. On a read-only
connection relay the unsaved result and web continuation. Saving a disclosure does
not order professional preparation, review, filing or payment.

If the journey or a required tool is unavailable, use the direct-authoring path
when it can fulfil the request, or give the record's web continuation. Do not
change an explicit destination, bypass a refusal, or claim a platform journey ran.
