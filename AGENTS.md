# Public repository instructions

This repository is public. Treat every GitHub write as publication, including
files, commit messages, branch and tag names, PR titles and descriptions, comments,
release notes, logs, screenshots, and packaged artifacts. Draft PRs are public too.

- Describe public product behavior using public product names, documented API/tool
  names, and public package versions.
- Do not add internal organization or repository names, private links or PR
  references, internal ticket IDs, codenames, backend release versions, deployment
  procedures, infrastructure details, credentials, or customer data.
- Keep internal evidence and cross-repository coordination in private records.
  Private records may link to public work; public content must not link back to
  private records. Do not copy internal release notes or agent transcripts here.
- Existing disclosures are not permission to repeat them. Do not include actual
  internal identifiers even as prohibited examples in public policy or checks.
- Before publishing, review the complete outgoing content and metadata, including
  every outgoing commit and generated artifact. CI and review after publication
  cannot prevent the initial disclosure.
- If disclosure is uncertain, omit the detail and resolve it privately with a
  maintainer. Report existing leaks privately; do not quote them in a public issue.

Read `README.md` for repository-specific work. Keep `AGENTS.md` and `CLAUDE.md`
equivalent when updating this policy.
